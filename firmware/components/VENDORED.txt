Vendored from https://github.com/CamM2325/microlink at commit 216da33 (MIT). Local changes are listed below.
Local patch: ESP-IDF 6 support (cJSON managed component), see CMakeLists.txt + idf_component.yml.
Local patch: ESP-IDF 6 / mbedTLS 4 support (private chachapoly headers, PSA RNG for the DERP TLS
link instead of entropy+ctr_drbg, esp_driver_uart/gpio instead of driver, GCC 15 warning flag).
All guarded by ESP_IDF_VERSION_MAJOR, so ESP-IDF 5.x builds are unchanged.

Note: microlink's WireGuard netif is added to lwIP directly, with netif->state
pointing at the WireGuard device. esp-netif must not read netif->state as its
own pointer, so sdkconfig.defaults sets CONFIG_LWIP_PPP_SUPPORT=y, which
switches esp-netif to netif client data (LWIP_ESP_NETIF_DATA=1). Without it,
IDF 6.x crashes in esp_netif_is_netif_up when the tunnel comes up.

Local patch: ML_DERP_REGION (home DERP relay, hardcoded to 9/Dallas upstream)
is a Kconfig option, CONFIG_ML_DERP_REGION; sdkconfig.defaults sets 4 (Frankfurt).

Local patches (call audio):
- wireguardif.c hands decrypted packets to netif->input (tcpip_input, set by
  microlink) instead of calling ip_input from the WireGuard task, which raced
  the TCPIP thread and crashed in udp_input on incoming RTP.
- ml_udp.c takes the lwIP core lock (CONFIG_LWIP_TCPIP_CORE_LOCKING=y) around
  raw udp_* calls, which are made from app tasks; ml_wg_mgr.c holds it while
  processing received WireGuard packets.
- Per-packet logs (WG RX/TX, UDP RX, DERP TX) are debug level instead of info.
